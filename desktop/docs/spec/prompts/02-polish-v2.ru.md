## Жёсткие правила

- Только Python + PyQt5/Qt Widgets. Без веба, Electron, QtWebEngine. Интерфейсы — приложение и CLI; агенты — через локальный MCP.
- Не писать второй краулер/анализатор/хранилище задач. Всё через ядро `Work/tools/seotools` (CLI/MCP). Нужна новая возможность ядра — issue → ветка в `seotools/worktrees/<задача>` → PR в `PavloSEO/seohead-tools`.
- UI-поток не делает SQL, сеть, сканы, разбор больших файлов. Модели и кэши ограничены.
- В реальном режиме нет слова «Демо». Демо-фикстуры — только `--capture`, тесты, галерея.
- Реальные сканы — **только локального QA-сайта** `examples/qa-site/qa_site.py` (профили `broken`, `clean`, `fix-delta`, `tracking`). Боевые и клиентские сайты, платные провайдеры, публикации — только с явного «да» Павла.
- Коммиты по-русски, **без `Co-Authored-By`**. Push в `origin` (`PavloSEO/seohead-desktop`, private) — после зелёных тестов этапа. Перед правкой — чистый `git status` (в рабочей копии сейчас незакоммичены `README.md` и `ui/i18n.py`, `ui/translations.py` от прошлой сессии: сначала разберись, доведи и закоммить их отдельно).
- Иконки — Material Symbols Outlined, локальные SVG из `google/material-design-icons` с записью commit/hash и Apache-2.0 NOTICE в asset-манифесте. Нужной иконки нет — рисуешь свою в той же сетке 24 px и подписываешь в манифесте как собственную.
- Минимальное окно **800×800**, основная ширина 1440. Проверяй обе.

## Этапы

**Этап 1. Дизайн-система в коде.**
`theme/tokens.json` → v2 по §2 дизайн-системы (роли, пары бейджей, данные, типографика, размеры каркаса, плотность, движение). Генерация QSS из токенов в Python (один `theme.qss`-шаблон, без строк стилей в экранах). Компоненты §3 через dynamic properties + `unpolish/polish`. Упаковать Roboto/Roboto Mono (OFL) и SVG-иконки. Делегат таблицы рисует бейджи HTTP/индексации и «Нет данных». Галерея компонентов (`ui/gallery.py`) показывает все состояния — скриншот галереи = доказательство этапа.

**Этап 2. Каркас окна.**
Одна шапка 52 px: знак + проект/сайт + запуск + статус агента + ⌘K + «Новый скан». Полоса вкладок рабочей области 36 px (вкладка = раздел + объект; меню ПКМ; «+» → экран «Новая вкладка»). Навигация 200/rail 64, группы «Данные», «Результат». Статус-бар. Убрать 15 вкладок «Проекта», которые дублируют навигацию. Пустые состояния с действием. Автосворачивание по ширине всегда, и после ручного ☰ тоже.

**Этап 3. Экраны по канвасу**, по одному, в порядке сценария: Старт → Работа → Новый скан (4 источника, включая **«Список URL»**: ядро уже поддерживает `input_mode=list`) → Сканы/наблюдение → URL-инспектор (вариант A по умолчанию, B — переключатель раскладки) → Проблемы → Сравнение → Отчёты и задачи исполнителям → Входящие → Поиск в HTML → Методы → Журнал → ⌘K → Настройка вкладок. Для каждого экрана: скриншот 1440 и 800 через `capture.py`, сравнение с канвасом, список расхождений. Закрыты пункты топ-15 из инвентаря — отметь, какие.

**Этап 4. Пробелы ядра** (отдельные issues/PR в seohead-tools, маленькими вертикалями):
`scan-url-query` (фильтры и сортировка по всему скану, курсоры, total) · исходящие ссылки одного URL · раздел HTML-тела в `scan-url-detail` · постраничное чтение журнала · локальный адаптер отправки скана через общий job-backend вместо прямого QProcess. Отчёты (`report_build`, `scan_export`), Извлечение (`scan_extract`), Методы (`skill_list/show`), Проблемы (`findings_view`, `remediation_*`) — есть в ядре, нужны адаптеры в Desktop + белый список `mcp_gateway.py`.

**Этап 5. Сквозной сценарий на QA-сайте — главный критерий приёмки.**
Подними `qa_site.py` профиль `broken` → скан №1 из приложения → агент через MCP создаёт задачи (программист / SEO / контент), ты видишь их в «Работе» и «Отчётах» → переключи сайт на `fix-delta` или `clean` → скан №2 по **списку URL** из задач и полный → «Сравнение» показывает исправленное/ухудшившееся, задачи закрываются только с доказательствами перепроверки. Сними весь путь скриншотами и запиши в `evidence/`. Где ядро не отдаёт метрику (например, слова/перелинковка по сегменту) — честное «Нет данных» и issue.

**Этап 6. Сборка и бренд.**
Иконка по §5 дизайн-системы: SVG → `.icns`/`.ico`/PNG. `scripts/build_macos.sh`, подпись, `scripts/smoke_bundle.py`. Обновить `dist/SEOHEAD Desktop.app` (ярлык `Приложение.app` в папке ТЗ на него указывает), старые `dist/*.app` — в Корзину. Linux/Windows — только сборочные скрипты, отметить «не проверено на ОС».
