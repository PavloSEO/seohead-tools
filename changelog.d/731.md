- Add `metrika-traffic-pdf` (`seo_metrika_traffic_pdf`): a static, A4-landscape traffic report in
  the layout of a analytics dashboard, built from Yandex Metrika. Collection and rendering are
  separate stages. Collection reads the Reporting API (about 40 free, read-only requests) into one
  `seohead.metrika-traffic/1` document: nine KPI cards (users, visits, pageviews, pages per visit,
  visits per day, bounce rate, average visit duration, share of visitors with two or three visits,
  share of new visitors) with changes against the previous period of equal length and the same
  dates a year earlier; daily dynamics; 3/6/12-month windows against the windows before them;
  search engines, cities, countries, devices, age, gender, top landing pages and search phrases;
  and all traffic channels. Rendering formats that document into self-contained HTML with inline
  SVG charts and prints it to PDF through a locally installed Chrome, Edge or Chromium
  (`SEOHEAD_CHROME` overrides discovery). Branding (name, colours, font stack, logo text) and
  English or Russian labels are inputs; Search Console query rows can be added as an optional
  page.

  Attribution defaults to the last significant source (`ym:s:lastSignTrafficSource` and its
  engine and phrase dimensions), which is what Metrika's interface reports; the last-click
  dimensions differ from it by a few percent and remain an explicit `attribution=last_click`.
  Every request passes `offset=1` because the API counts rows from 1. Missing data stays
  visible: each block carries `ok`, `unavailable` or `skipped` with a reason, a change without
  a baseline is `null` rather than zero, a missing browser leaves the HTML and reports the PDF
  as skipped, and existing files in `out_dir` are replaced only with `overwrite=true`.
