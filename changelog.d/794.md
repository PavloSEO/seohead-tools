- Project checklists can now record the agreed audit scope and report honest coverage
  ratios (#794). `project-checklist-init` / `seo_project_checklist_init` accept an optional
  `plan` — a reviewer plus a URL `population` declared as a `complete_set`, a named
  `sample`, or `unknown`, with its `source`, `size` or enumerated `urls`, and optional
  per-`templates` populations — bound to the project site identity and stamped with the
  write revision. Recording a plan upgrades the checklist to `seohead.coverage.v3`;
  reading, reconciling, or applying priorities never upgrades or invents a population,
  and v1/v2 documents keep loading unchanged.
- Checklist status now returns `coverage`: five separate ratios — `audit_tasks`,
  `checks` (with `measured_urls`), `manual_review`, `deliverable_review`, and
  `url_population` — each with its own `basis`, `numerator`, `denominator` and `state`,
  so a URL count is never mixed with a check or task count. A denominator that cannot be
  justified stays `null` with `state: "unknown"` and a reason instead of becoming 0/0 or
  100%; measurements that cannot be verified against the agreed population keep the URL
  axis `partial` and count only verified eligible URLs. Saved check evidence now carries
  the measured URL enumeration, so the URL numerator is an auditable set rather than a
  row count. Multi-site aggregation sums the axes per site and degrades to `unknown`
  whenever a site cannot justify its denominator.
- A `not_applicable` record is now a reviewed exclusion: it requires a reason, a
  reviewer, and an inspectable evidence basis — a project-relative digested `artifact`
  or an explicit `evidence` reference. Reviewed exclusions keep their stable ID and
  history, leave the task denominators only through that recorded decision, and are
  listed separately under `exclusions`. A disabled item, a stale exclusion record, or a
  legacy `not_applicable` record written before the evidence-basis rule stays inside the
  denominator as `pending_exclusion` until reviewed again, so disabling, catalogue
  removal, or reclassification can never silently shrink agreed counts.
