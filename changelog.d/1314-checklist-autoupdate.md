- A saved project crawl now marks the automatic checklist items it measured. Each enabled check item resolves to one of three outcomes: `succeeded` when the saved audit ran the check, with the scan as evidence; `unavailable` when the crawl skipped or disabled it, with the crawl's reason kept; or `unmeasured` when the audit does not mention the check at all. An unmeasured item keeps its previous record and is reported by name in `checklist_evidence`, so it never counts as 0. A crawl that fails or is interrupted marks its automatic checks `failed` with the failure reason. The same recording path now serves the `prepare` flow, which previously carried its own copy of the loop. A project whose checklist is not initialized is skipped with a stated reason.
