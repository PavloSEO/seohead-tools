- Saved scans open lightly for reads (#931). `scan-status`, `scan-url-detail`, `scan-link-inspect` and the project observer (`project-scans`, `project-observe`) no longer validate the whole artifact on every open: they check identity, schema, version and the header row, take counters from SQL (`GROUP BY` over `pages_status`), and say so in an additive `validation` field (`"light"` or `"full"`). Full validation runs on request (`full_validation: true` on `scan-status`, or `--input '{"input_path": "...", "full_validation": true}'` on the CLI) or when the same bytes (path, size, mtime, WAL state, header hash) were already fully validated in the process; a scan that fails the light checks is refused with the same error as before, and every writer or evidence-recording path still validates fully. `scan-url-detail` runs the redirect-target lookup (no index on `responses.effective_url_id`) under a 0.5 s budget and reports `responses.redirect_target_lookup` as `skipped` instead of scanning a large table.
